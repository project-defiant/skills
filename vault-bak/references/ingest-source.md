# Mode: ingest-source

Ingest an external source (URL, PDF, local file, pasted transcript) into a project's `Research/sources/` and write an LLM summary that links to it.

## Inputs

- **source** (required): URL, absolute file path, or a paste block explicitly marked as source content.
- **project** (optional): resolved via project routing (see `SKILL.md`) if missing.
- **summary_hint** (optional): user-provided angle to emphasise in the summary.

## Steps

1. Resolve **project** via project routing. If it doesn't exist, run `project-init` first.
2. Set `DEST="$SZYMON_WIKI/Projects/{project}"`.
3. Determine source type:
   - URL → `article` (fetch with WebFetch, prefer markdown extraction)
   - `.pdf` → `pdf` (Read via the Read tool for text extraction, or save the file verbatim)
   - `.md` / `.txt` → `text`
   - pasted block → `transcript`
4. Derive **title** and **slug**:
   - Title from the page's `<h1>` / document title / user hint / URL path.
   - Slug: lowercase, spaces → dashes, strip non-alphanumeric-dash. Max 60 chars.
5. Write raw source to `$DEST/Research/sources/YYYY-MM-DD-{slug}.md` with a small YAML header noting the fetch time and origin URL, followed by the raw content. For PDFs, copy the file verbatim as `.pdf` (do not re-encode).
6. Write summary to `$DEST/Research/{slug}-summary.md` using the summary template below.
7. Suggest KB concepts:
   - Extract 3–7 salient technical terms from the summary.
   - For each, ripgrep `$SZYMON_WIKI/KnowledgeBase/` for a matching page.
   - If not there, ripgrep `/Users/ss60/Documents/v/KnowledgeBase/` (read-only). If matches exist there, OFFER copy-on-first-use for each:
     > Found `[[{term}]]` in the wider vault's KnowledgeBase. Copy into the wiki so ingest-source can link it? (y/N)
   - Never auto-copy. Never auto-create new KB pages here — that's a `promote` job.
8. Update `$DEST/index.md`:
   - Under `## Research`, replace the placeholder if still present.
   - Append `- [[{slug}-summary]] — one-line — source: [[YYYY-MM-DD-{slug}]]`.
9. Append project log entry:
   `- YYYY-MM-DD HH:MM — ingest-source — {title} — [[{slug}-summary]]`
10. Append global log entry:
   `- YYYY-MM-DD HH:MM — [[{project}]] — ingest-source — {title} — [[{slug}-summary]]`
11. Report all created paths to the user.

## Templates

### `$DEST/Research/sources/YYYY-MM-DD-{slug}.md` (raw)

~~~
---
source_url: {url_or_path}
source_type: {article|pdf|text|transcript}
fetched_at: {YYYY-MM-DD HH:MM}
title: {title}
---

{raw content as fetched — do NOT edit this file after writing}
~~~

### `$DEST/Research/{slug}-summary.md`

~~~
---
title: {title} — summary
source: {url_or_path}
source_file: [[YYYY-MM-DD-{slug}]]
project: [[{project}]]
ingested_at: {YYYY-MM-DD HH:MM}
tags: []
---

# {title}

**One-liner**: {≤ 25 words}

## Key claims

- ...

## Methods / mechanism (if applicable)

- ...

## Open questions

- ...

## Related concepts

- [[Concept A]]
- [[Concept B]]
~~~

## Notes

- The raw source is IMMUTABLE. Corrections or reactions go in the summary or in a new note under `Research/`, never by editing the raw file.
- If the URL later 404s, the raw copy is what you still have — that's the point.
